# 权限模型（Permission Model）

- 状态：**已批准**（批准范围：Slice Agent-1 最小单轮意图路由——仅 L0/L1 只读/分析 A 类；写类 L2/L3 与 B/C/D 确认政策待后续写能力实施时启用）
- 依据：`AGENTS.md` §19/§30/§31；Step 5 Agent 能力与权限设计（已确认）

---

## 1. 行为等级（L0–L3）

| 等级 | 名称 | 本质 | 持久写入 |
|---|---|---|---|
| **L0** | 只读/查询 | 读取资产/字段/指标/工作台/规则/历史 | 否 |
| **L1** | 分析/推理/建议 | 计算、分析、解释、归因、推荐、临时洞察 | 否（瞬时） |
| **L2** | 低风险写入 | 创建/修改**可逆、非破坏、不触原始数据**的对象与配置 | 是（可逆） |
| **L3** | 高风险写入 | 原始数据/破坏性/高影响结构/外部副作用/持续自主行为 | 是（高影响） |

## 2. 确认政策（A/B/C/D）

| 政策 | 含义 | 适用边界 |
|---|---|---|
| **A** | 直接执行 | 只读/查询/分析/推理/建议（无持久写入） |
| **B** | 首次确认，之后可自动 | **仅限** 可逆、无外部副作用、无自主持久行为、不触原始数据 的低风险创建/配置；可随时关闭 |
| **C** | 每次确认 | 持久对象写入/修改/删除；结构/映射/原始数据修改；自主行为创建 |
| **D** | 永远禁止自动执行 | 原始数据删除；权限/账号/安全；不可逆外部副作用（Agent 只能警告/说明，用户亲自执行） |

> **B 的硬边界**：一切删除、原始数据变更、自主行为，**永不进入 B**。

| 域 | 操作 | Level | 确认 |

## 4. 特别明确（必须逐字遵守）

- 只读/分析 = **A**
- 低风险可逆写入 = **B/C 规则**（按上表）
- 高风险写入 = **C**
- **删除原始数据 = D（永不自动）**
- **修改原始数据 = C（每次明确确认）**
- **修改 Field Type = C（每次明确确认，高危）**
- **修改 Data Source Mapping = C（每次明确确认，高危）**
- **权限/账号/安全 = 不允许 Agent 自主执行**
- **外部副作用 = 不允许 Agent 自主执行**
- **自主/定时行为 = 授权式确认（C），默认只读分析，可随时撤销**

## 5. 执行权判断规则（命中即停）

```
Q1 只读/查询/分析/推理/建议（无持久写入）→ 直接执行（A）
Q2 触原始数据？
   ├─ 删除/不可逆破坏 → 永不自动（D）
   └─ 修改/结构（Field Type/Mapping）→ 每次确认 + 影响预览 + 可回滚（C）
Q3 创建"未来自主行为"（定时/自动/提醒/报告/监测规则）？
   ├─ 是 → 授权式确认，默认只读、可撤销（C）
   └─ 否 → Q4
Q4 创建可逆知识资产（metric/派生字段/模块/挂载/报告/工作台）？
   ├─ 是 → 提案/预览 → 确认 → 执行（C 或 B）
   └─ 否（纯布局/偏好，可逆）→ 直接或 B
```

## 6. 统一写流程

```
Proposal → Confirmation → Execute → Result → Activity Log
```

- 目标对象在确认执行后由 `Draft/Proposed` → `Active`。
- 执行只由 **Application** 完成；Agent 只产生 Proposal。
- 所有结果入 Activity Log。

## 7. 风险分级视觉语义（Confirmation Card 对应）

- low/med：中性卡片 + accent 边框；默认显示 做什么/为什么/改什么 + 确认/修改/拒绝/忽略。
- high：amber 强调 + **强制展开影响与可撤销** + 风险标签 + 更高确认意图（如勾选"我理解此操作会影响已有数据"）。
- 展开项：影响范围 / 可撤销性 / 涉及数据 / 涉及工作台与模块 / 置信度 / 详细 diff。
