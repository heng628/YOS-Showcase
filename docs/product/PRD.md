# 产品需求文档（PRD）

> 项目：YOS — AI 数据资产工作系统
> 依据：《AGENTS.md》总规则。本文把规则中的产品意图落到可执行的 PRD，供产品、设计、研发使用。

---

## 1. 产品定义

**一句话定义**

> 一个帮助用户沉淀、理解并利用自己数据资产的 AI 工作系统，数据会持续沉淀，AI 会越来越懂用户。

**它不是**

- 数据可视化 Dashboard
- 传统 BI 工具
- 只有聊天框的 AI 产品

**它的核心闭环**

```
数据资产 → AI 理解 → 分析 → 监测 → 建议 → 用户决策 → 数据继续沉淀
```

---

## 2. 目标用户与场景

第一阶段面向**个人用户**，未来扩展团队与企业。核心用户是「有自己数据、需要持续分析与决策」的人，例如：电商运营、内容运营、新媒体主理人、产品运营、自由职业者、学习者、项目负责人。

典型诉求（来自总规则愿景清单）：

| # | 用户诉求 |
|---|---------|
| 1 | 手动输入数据 |
| 2 | 导入 Excel / CSV / JSON 等数据 |
| 3 | 通过 API 自动获取数据 |
| 4 | 通过 OAuth / 登录账号连接第三方平台 |
| 5 | 建立自己的数据资产 |
| 6 | 自定义字段和字段映射 |
| 7 | 建立指标和数据关系 |
| 8 | 创建多个工作台（Workspace） |
| 9 | 使用 AI 分析自己的数据 |
| 10 | 设置自动分析和异常预警 |
| 11 | 生成数据报告 |
| 12 | 使用 AI Agent 执行数据相关任务 |

---

## 3. 核心产品模型

```
User
├── 1─N Space ── 1─N Workspace
├── 1─N Data Asset（用户级顶层共享，不属于任何 Workspace）
└── 1─N Metric（用户级知识资产）

Workspace ─ 1─N Mount ─ N─1 Data Asset（经 Mount 使用，不拥有）
Workspace ─ 1─N Module；Module N─M Metric；Module N─M Mount
DataAsset 1─N Field / Record；Metric N─M Field
```

> 注：数据归属以 `docs/architecture/domain-model.md` 为准。

| 对象 | 说明 |
|------|------|
| **User** | 产品用户（第一阶段个人为核心） |
| **Space** | 用户一级**工作场景分组容器**（工作、学习、个人等，**可自由增删改排，不硬编码为固定 enum**；不拥有、不隔离数据） |
| **Workspace** | 具体工作环境（电商经营、内容运营、项目 A…），承载数据/模块/指标/AI 分析/监测/报告/自动任务 |
| **Data Asset** | 用户真正拥有的**用户级顶层共享**数据资产（订单、商品、广告、客户、视频、学习记录…），**不绑定行业、不属于任何 Workspace**，可被多个 Workspace 经 Mount 复用 |
| **Field / Record / Metric** | 字段、记录、指标（含派生指标与 AI 指标） |
| **Module / Analysis** | 工作台内的模块与分析 |
| **Report / Alert** | 报告与预警 |

**关键约束**

- Space 类型**不得硬编码**为固定 enum，需支持用户新增/删除/重命名/排序/改图标/改主题。
- 一个 Data Asset 可被多个 Workspace 使用，**不得为不同 Workspace 复制同一份原始数据**。

---

## 4. 数据资产原则

数据资产必须支持：原始数据、字段、字段类型、字段映射、数据关系、派生指标、AI 指标、数据来源、更新时间、数据版本、数据健康度、历史记录。

用户获取数据的方式：手动创建、手动导入、自动同步、API 获取、未来通过 Agent 自动发现数据源。

---

## 5. 字段系统

字段系统高度通用，不绑定行业。支持的通用数据类型：

Text、Number、Integer、Currency、Percentage、Date、DateTime、Boolean、Single Select、Multi Select、URL、File、ID（未来可扩展）。

> 注意：**Formula 与 Relation 不是 Field 类型**——Formula 归入 Metric 定义/计算逻辑；Relation 是独立关系对象（V1）。

---

## 6. AI 数据理解（数据体检）

首次导入后，AI **不直接修改原始数据**，职责是：识别字段、推测字段类型、理解字段语义、识别字段关系、发现潜在指标、检查数据质量、提供推荐。

**核心原则**

```
AI 发现 → AI 解释 → 用户确认 → 系统执行
```

所有涉及原始字段修改、原始数据修改、字段删除、数据删除、数据结构重大变化的操作，**必须经用户确认**。

---

## 7. AI 推荐机制

AI 不一次性展示几十个指标，而是**推荐最有价值的几个指标**，并给出理由，例如：

> 「我发现你拥有 GMV 和广告费用数据，建议增加 ROI，因它能判断广告投入的销售效率。」[添加]

用户可：接受 / 拒绝 / 删除 / 暂时忽略。

AI 通过用户长期行为学习（关注、忽略、删除、常看、常用指标、认为无价值的预警），但**不设计明显的「AI 正在监控你」页面**。学习主要通过产品行为发生，目标是自然产生「它居然已经懂我的工作了」的惊喜感。

---

## 8. AI Agent（执行层）

Agent 是产品的智能执行层，通过工具调用：查询数据、分析数据、计算指标、创建字段/指标/模块/Workspace、创建自动分析任务、创建监测任务、生成报告、解释异常、查询历史数据。

**执行链**（Agent 不允许绕过权限系统直接修改原始数据）：

```
User Intent
↓
Agent Understanding
↓
Tool Calling
↓
Result
↓
Proposal / Preview
↓
User Confirmation
↓
Execution
```

只读操作可直执；高风险操作必须确认。

### 交互形态

「全局 Agent + 场景内 AI」结合：

- **全局 Agent**：`Ctrl/Cmd + K` 打开 AI Command Center，识别自然语言意图并调用工具。
- **场景内 AI**：数据资产页「分析这个数据」直接分析；工作台「为什么今天 GMV 下降？」基于当前 Workspace 上下文回答；指标页「帮我创建 ROI」生成定义并请求确认。

**重要**：不要单独设计一个「AI 页面」把所有 AI 功能塞进去；AI 是融入整个产品的一层能力。

### Agent 临时工作区

复杂任务可创建临时 Workspace。例如「帮我分析这个月利润为什么下降」→ 创建「利润下降分析」，包含数据、发现、AI 判断。用户可：继续分析 / 保存为报告 / 创建监测任务 / 关闭。

---

## 9. 智能监测

支持：自动分析、定时分析、条件触发、趋势检测、异常检测、AI 预警。

预警需逐渐理解用户。例如用户对某类异常说「不要提醒」，系统记录后默认不再提醒同类型；但当异常程度显著高于历史水平时，可再次询问是否重新关注。用户可：忽略一次 / 暂时关闭 / 永久关闭 / 重新关注。

---

## 10. 数据分析原则

**「能由确定性程序计算的，不交给 LLM 计算。」**

- 确定性计算（程序承担）：GMV、ROI、Conversion Rate、AOV、Growth Rate、MoM、YoY、Moving Average、统计指标。
- AI 负责：理解、解释、归因、推理、生成建议。

---

## 11. 工作台（Workspace）

模块数量不固定，用户可增加/删除/移动/调整大小/修改，也可由 AI 创建或推荐。提供**简单模式**（隐藏复杂配置）与**专业模式**（开放更多配置）。

核心原则：**「高自由度，但不让用户一开始面对高复杂度。」**

---

## 12. 数据资产中心

Data Asset 有独立入口，用户可查看：全部数据、数据分类、数据来源、更新时间、数据量、健康度、使用中的 Workspace、字段、指标、数据关系。用户看到的是「我的数据资产」，而非传统数据库后台；专业模式才显示更多技术细节。

---

## 13. 首次启动体验（Onboarding）

沉浸式，不直接扔进复杂 Dashboard：

1. 你准备在哪里使用它？（默认 工作/学习/个人，可新增）
2. 告诉我你想做什么？（自然语言，如「我是电商运营…」）
3. AI 理解并推荐 Workspace（如「电商经营」）
4. 选择配置方式（AI 帮我配置 / 我自己配置 / AI 辅助我配置）
5. 导入数据
6. AI 数据体检
7. 用户确认字段映射
8. 进入 Workspace

提供轻量级功能向导，不一次展示所有功能。

## 14. 产品信息架构

```
User
↓
Space
↓
Workspace
↓
Data Asset
↓
Module
↓
Analysis / Alert / Report
```

> 注：以上是**导航/信息层级**，不是数据归属；数据归属（Data Asset 属 User、Workspace 经 Mount 使用）见 `docs/architecture/domain-model.md`。

全局能力：AI Agent。

核心入口：**Spaces、Data Assets、Monitoring、Reports、AI Agent、Settings**。

Workspace Launcher 使用卡片形式，卡片用于「选择进入哪个工作环境」，不用于展示具体数据。

---

## 15. 非功能需求（NFR）

- **数据安全**：涉及用户数据必须考虑安全。
- **权限与确认**：涉及 AI 操作必须考虑权限和确认机制。
- **数据完整性**：不破坏已有数据，数据模型变更需说明迁移方案。
- **长期沉淀**：架构须为未来商业化（Plan / Subscription / Usage / 各功能用量 / Feature Permission）预留扩展点，但不因过早商业化破坏核心体验。

---

## 16. 版本范围

### MVP（优先证明「数据资产 + AI 理解 + AI 分析」）

包含：User、Space、Workspace、Data Asset、CSV/Excel 导入、手动数据输入、字段识别、字段类型识别、AI 字段语义识别、字段映射、数据体检、基础指标、工作台、AI 分析、AI Agent、基础异常检测、基础预警、临时报告/简单导出（**正式 Report 对象与报告中心在 V1**）。

**暂不做**：团队协作、企业权限、大量第三方 API、完整商业化系统、高级主题市场、复杂 Agent 自动化、多人实时协作。

### V1

加入：API 数据连接、OAuth、自动同步、数据版本、数据历史、AI 学习、自动分析、智能监测、报告、Agent 临时工作区、Theme System、更多数据源。

### V2

加入：Team Space、Enterprise Space、Permission、Collaboration、Advanced Agent、Long-running Agent Tasks、Cross-workspace Reasoning、Complex Workflow、Enterprise Data Integration。

---

## 17. 验收/评估原则（开发前自问）

开发任何新功能前判断：

1. 是否服务于数据资产？
2. 是否服务于用户工作？
3. 是否增强 AI 理解？
4. 是否增强用户决策能力？
5. 是否降低用户重复劳动？
6. 是否让系统更理解用户？
7. 是否增加不必要复杂度？

若功能「看起来很酷」但无法服务核心闭环（数据资产 → AI 理解 → 分析 → 监测 → 建议 → 用户决策 → 数据继续沉淀），则降低优先级。
